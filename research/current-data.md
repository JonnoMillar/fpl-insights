# Current data audit

Audited 21 October 2026 against local commit `5546ef79a146f00b0d7684066174760be7121abf`. This is a source-code and existing-cache audit, not a claim that the providers were freshly contacted. The current README describes the broad architecture correctly, but omits the all-player gameweek harvest and the now-consumed FFS fixture-projection blob. Production files and generated outputs were not changed for this audit.

**Main finding:** the application already has PL match histories, set-piece orders, defensive contributions, transfer/price signals, BPS, seven extra Opta statistics, fixture projections and market prices. The larger gaps are provenance/freshness, competition coverage, role changes, market history and validated uncertainty—not simply a lack of more season totals. Some useful fields are already downloaded but unused. Pulselive's four-page cap demonstrably omits its fifth page of touches in the inspected cache.

## Scope and reading key

The ingress search covered every root Python and JavaScript file, `.github/workflows/build.yml`, `config.json`, `price_history.json`, `projections.json`, `README.md`, and the recent handoff. Every HTTP implementation is in `fplapi.py`, `ffs.py`, `odds.py` or `pulse.py`; the browser scripts do not fetch football data. `graphify-out/graph.json` was absent; no graph or dependency was created. Cached schemas/counts were inspected without copying managers' personal rows into this report.

In the tables, **model** means a field affects forecast values, selection/ranking, eligibility or affordability; **display** means it is explanatory/visible without being an xP input; **join/control** means identifiers, pagination or fixture validation. **Cached** is not the same as used: the clients generally save whole provider responses.

## Broad passthrough and browser payloads

These cases are intentional payload breadth, not proof that every downloaded property affects advice:

1. JSON fetchers cache whole provider responses. `Ctx` retains raw bootstrap and fixtures; `PlayerReport` retains entire current/past histories; public picks retain whole objects and acquire `element_obj`. Only named reads above affect behavior.
2. `scout.raw_rows` emits the whole eligible outfield pool with at least one season minute, not only the initially filtered shortlist. It includes per-GW `matches`, availability, duty booleans, raw/rate metrics and contextual counts. `scout.js` recomputes percentiles, z-scores, archetypes and filter results when filters change. This breadth is necessary for offline filtering; it is **not** a second remote feed or proof that every metric drives xP.
3. `season_live` retains `goalsConceded`, `bonus`, `bps` and other per-GW fields in match dictionaries even where the current position configs do not render a sparkline for them. Planner uses only the start-state series from this history. The source's richer raw CBIT components and explain-stat breakdown are not copied through.
4. `player_payload` emits the full available seven-stat `_pulse` dictionary as `opta`, plus full xP explanation dictionary and normalized last-season object. `playerview.js` generically enumerates nonzero Opta fields. All seven Opta statistics therefore have a real display consumer even though only big-chance measures have dedicated leaderboard/findings cards.
5. `price_watch` reads `price_change_projections[].offset`, `.projected_percent`, `.likelihood` and retains the raw element in each Python row. Current `price_row` displays only the chosen projection percent; `likelihood` and the retained raw element do not affect rendered advice. Offset 2 falls back to 1/0, while the copy still says "in two days".
6. Pinnacle BTTS is genuinely computed but currently unused: `market_card` is a remaining callable renderer, not part of `dashboard.build`. The live market consumer is `odds_insights`. The source still must not be described as individual-player scoring odds.
7. `projections.json` is an **output**, never an input to this repository. It exposes `gw`, `generated`, `xp` to the separate phone-alert project. Own/history-backed predictions and market-wide/bootstrap predictions coexist in that map. Unsupported planning uses `gw=null`/empty predictions rather than a valid-looking requested week. The companion bot's own FFS/news ingestion is outside this repository and not counted here.

## Current limitations and useful data gaps

| Finding | Evidence and practical effect |
|---|---|
| Source freshness/provenance is incomplete | Health stores `{ok, detail}`, without retrieved-at/provider-as-of/age/coverage. Bootstrap `news_added`, league `last_updated_data`, event-live `modified` and summary history `modified` are ignored. FFS extraction discards editorial timestamps. A successful cached parse is reported OK even if its football assessment is old. Existing generation-age warning cannot detect this. |
| Pulselive coverage is incomplete today | Four-page maximum vs cached touches `numPages=5` omits the fifth page. Six other stat categories currently fit. Per-stat/page failures can still yield overall `Opta stats: OK` because health requires only some joined stats. Missing and zero must remain distinct; several display paths suppress zero-valued stats. |
| No independent season alignment for supplemental sources | Pulse resolves season from latest completed PL fixture; FFS uses club/GW strings; no provider-season token is cross-checked to bootstrap. Fixture opponent/venue checks reduce contamination for planning, but cannot prove source season/as-of correctness. |
| Fixture guards differ by consumer | `Ctx.scoring_fixture` binds xP to exact FPL GW/opponent/venue and market kickoff date; dashboard withholds planning across unsupported doubles/incomplete eight-week window. Decorative `ticker._rows_for` market replacement checks first cell/opponent only; `odds_insights` checks opponent/venue but not date. Missing FFS rows default to `blank` in generic ticker/Scout paths; owned-player dialog additionally consults actual FPL fixtures and labels missing/unsupported rows unavailable. |
| PL playing time exists; all-competition burden does not | Owned per-fixture PL reports, all-player per-GW starts and planner last-three/season reversion already exist. No Europe/cup/international minutes, training evidence, travel/rest or congestion calculation is ingested. Do not call this an absence of recent-minute history. |
| Availability is sparse and callers use it differently | FPL status/chance/news + FFS predicted starters are consumed. No timestamped official injury/return evidence, confidence/evidence ledger or expected return timeline. Planner uses a flat assumption after a 0% first week. Candidate scorer itself does not scale by stated fitness chance, unlike the owned scorer and planner. |
| Role/chance quality is mostly season-aggregate | No shot locations/body part/open-play-v-set-piece/penalty flag, position/role timeline (CB/FB/WB), touch maps, or recent per-match Pulselive advanced counts. Seven current extra Opta season totals explain performance but do not alter forecasts. Current FPL set-piece order is already present; observed duty shares/change evidence is missing. |
| DefCon data exists; forecasting remains approximate | Owned forecasts use observed match threshold hits. Scout uses per-GW totals/hit rate with multi-fixture weeks excluded; candidate scorer still uses a season-rate-to-threshold curve. Raw component fields exist but are unused. No opponent-adjusted empirical hit distribution/minute-conditioned model or calibration of Scout's opponent-xG DefCon-difficulty proxy. |
| Market snapshot only | Latest Pinnacle totals/spreads/team-goals/to-score/moneylines are ingested, with quoted CS preferred where available. There is no opening/current/closing time series, movement signal, bookmaker dispersion or out-of-sample test of market-v-FFS disagreements. `by_club` keeps only the soonest priced fixture per club. |
| Forecast comparability/uncertainty | Two substantive scorers remain: owned history-backed xP and season/price-prior candidate xP, with different rate blending, minutes and fixture clamps. Multiweek planner uses candidate scorer plus start overrides; first-week captain is reconciled to owned ranking. Handoff records the visible 64.8/66.1 pitch versus 70.0 plan example. No immutable prediction-v-outcome ledger, backtest, probability intervals or learned calibration; elite ownership's margin of error is a separate sample statistic, not forecast uncertainty. |
| Public-state and sample limits | Public picks/bank/FT replay cannot see already-made next-week changes. Purchase recovery can fail. Dashboard first-page/top25 cap can omit a larger mini-league; duplicate entry names key `by_name` and histories, potentially collapsing managers. Elite top250 + last-season top100k qualification is a selected sample; fewer than 50 qualifiers suppresses analysis, but after picks failures the minimum is not rechecked. |
| Health coverage is narrower than all ingress | Core bootstrap/fixtures and optional FFS/Pulse/Scout/recommendation/selling/preview paths record health. Elite failure/insufficient samples, skipped rival/league picks/history/live requests, chip-history failure, image failures and price-memory write failure are not uniformly included in health. Some failures are console-only or explained in their own component. "All health entries OK" does not mean every external request/field was complete. |

The highest-value investigations for an expanded decision system are therefore: all-competition minutes/rest; timestamped availability evidence; shot/role and observed set-piece changes; reusing existing event history/components for calibrated DefCon distributions; market movement history; and immutable forecast/outcome evaluation. These are research directions, not authorization to add providers or alter the model.
